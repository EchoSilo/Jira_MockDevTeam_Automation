<feature>
  <name>ScheduledAction Model (TDD)</name>
  <files>src/scheduling/models.py, tests/test_scheduling_models.py</files>
  <behavior>
    ActionStatus enum: PENDING, READY, COMPLETED, SKIPPED, ADAPTED

    ScheduledAction dataclass with @dataclass(order=True):
    - scheduled_time: pendulum.DateTime (comparison key for heap)
    - action_id: str (default: uuid4()[:8], compare=False)
    - action_type: str (compare=False)
    - agent_id: str (compare=False)
    - ticket_key: str (compare=False)
    - scenario_id: Optional[str] (compare=False)
    - window_minutes: int = 30 (compare=False)
    - expected_status: Optional[str] (compare=False)
    - expected_assignee: Optional[str] (compare=False)
    - status: ActionStatus = PENDING (compare=False)
    - executed_at: Optional[pendulum.DateTime] (compare=False)
    - result: Optional[dict] (compare=False)
    - params: dict = {} (compare=False)

    Methods:
    - is_due(current_time) -> bool: scheduled_time <= current <= scheduled_time + window
    - is_overdue(current_time) -> bool: current > scheduled_time + window
    - mark_completed(result: dict) -> None: status=COMPLETED, executed_at=now
    - mark_skipped(reason: str) -> None: status=SKIPPED, result={"reason": reason}

    Test cases:
    - action.is_due(scheduled_time + 15min) returns True (within 30min window)
    - action.is_due(scheduled_time - 1min) returns False (before window)
    - action.is_overdue(scheduled_time + 31min) returns True (past window)
    - mark_completed sets status and executed_at
    - Comparison uses scheduled_time only (for heap ordering)
  </behavior>
  <implementation>
    Use @dataclass(order=True) with field(compare=False) for non-comparison fields.
    Use pendulum.duration(minutes=window_minutes) for window calculations.
    Import uuid for action_id generation.
  </implementation>
</feature>

<feature>
  <name>ActionPriorityQueue (TDD)</name>
  <files>src/scheduling/priority_queue.py, tests/test_priority_queue.py</files>
  <behavior>
    ActionPriorityQueue class using heapq:
    - _heap: List[ScheduledAction] (internal storage)

    Methods:
    - push(action: ScheduledAction) -> None: heappush O(log n)
    - peek() -> Optional[ScheduledAction]: return _heap[0] or None
    - pop() -> Optional[ScheduledAction]: heappop or None
    - get_due_actions(current_time, max_actions=10) -> List[ScheduledAction]
    - cancel_action(action_id: str) -> None: mark status=SKIPPED (not remove)
    - size() -> int
    - is_empty() -> bool

    get_due_actions behavior:
    - Iterate heap (already sorted)
    - Return actions where is_due(current_time) AND status == PENDING
    - Stop at max_actions or when scheduled_time > current_time
    - Do NOT remove from heap (executed actions marked, not removed)

    Test cases:
    - push 3 actions with different times, peek returns earliest
    - pop returns actions in scheduled_time order
    - get_due_actions returns only PENDING actions within window
    - get_due_actions respects max_actions limit
    - cancel_action marks status=SKIPPED (not removes)
    - canceled actions excluded from get_due_actions
  </behavior>
  <implementation>
    Use heapq.heappush/heappop. Heap is sorted by scheduled_time because
    ScheduledAction uses @dataclass(order=True) with scheduled_time first.

    For get_due_actions, iterate rather than pop (leave actions in heap).
    Mark actions SKIPPED instead of removing (heapq doesn't support efficient removal).
  </implementation>
</feature>
