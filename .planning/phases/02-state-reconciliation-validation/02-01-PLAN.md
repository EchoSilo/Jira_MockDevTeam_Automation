  <behavior>
    ValidationResult(valid=True) when:
    - validate_status("ESCRUM-123", "In Progress") and ticket is "In Progress" -> valid=True
    - validate_sprint_membership("ESCRUM-123", expected_in_sprint=True) and ticket in active sprint -> valid=True
    - validate_with_timestamp("ESCRUM-123", "In Progress", last_known="2026-01-28T10:00:00+00:00") and ticket.updated <= last_known -> valid=True

    ValidationResult(valid=False, reason="...") when:
    - validate_status("ESCRUM-123", "In Progress") and ticket is "Done" -> valid=False, reason="Status changed: expected 'In Progress', got 'Done'"
    - validate_sprint_membership("ESCRUM-123", expected_in_sprint=True) and ticket NOT in active sprint -> valid=False, reason="Sprint membership changed..."
    - validate_with_timestamp("ESCRUM-123", "In Progress", last_known="2026-01-28T10:00:00+00:00") and ticket.updated > last_known -> valid=False, reason="Optimistic lock failed..."

    Error handling:
    - Jira API returns 404 -> valid=False, reason="Jira API error: Issue not found"
    - Jira API timeout -> valid=False, reason="Jira API error: Connection timeout"
  </behavior>
  <implementation>
    1. Create src/reconciliation/models.py with ValidationResult dataclass:
       - valid: bool
       - reason: Optional[str] = None
       - actual_state: Optional[dict] = None

    2. Create src/reconciliation/validators.py with:

         - __init__(self, jira_client: JiraClient)

       - OptimisticLockingValidator class:
         - __init__(self, jira_client: JiraClient)
         - validate_with_timestamp(ticket_key, expected_status, last_known_updated) -> ValidationResult
         - Uses pendulum.parse() for timestamp comparison (per Phase 1 patterns)
