<feature>
  <name>Confidence Tracker with Accept Reality Mode</name>
  <files>src/chaos/confidence_tracker.py, tests/test_confidence_tracker.py</files>
  <behavior>
    ConfidenceScore dataclass:
    - script_fidelity: float (0.0-1.0)
    - total_events: int
    - executed_as_planned: int
    - adapted_events: int
    - external_overrides: int
    - positive_adaptations: int (terminal status reached early - good)
    - accept_reality: bool

    ConfidenceTracker class:
    - __init__(threshold: float = 0.7, override_limit: int = 3)
    - calculate_confidence(scenario: SprintScenario) -> ConfidenceScore
      - total_events = count all events in script
      - For each executed event:
        - If execution_result.adapted == True: adapted_events += 1
        - If execution_result.external_override == True: external_overrides += 1
        - If execution_result.positive_adaptation == True: positive_adaptations += 1
        - Else: executed_as_planned += 1
      - script_fidelity = (executed_as_planned + positive_adaptations) / total_events
      - accept_reality = fidelity < threshold AND external_overrides >= override_limit
    - should_accept_reality(scenario: SprintScenario) -> bool
      - Convenience method returning calculate_confidence().accept_reality
    - is_positive_adaptation(event_result: dict) -> bool
      - True if target status is terminal (Done, Closed, Resolved)
      - True if event completed ahead of schedule
      - Helps distinguish good adaptations from bad

    Tests (pytest tests/test_confidence_tracker.py):
    - Perfect execution: fidelity = 1.0
    - All events adapted: fidelity = 0.0
    - Mixed execution: fidelity proportional
    - Early completion (positive adaptation) doesn't hurt fidelity
    - Accept reality triggers at < 0.7 with 3+ overrides
    - Accept reality does NOT trigger if fidelity low but < 3 overrides
    - Accept reality does NOT trigger if 3+ overrides but fidelity >= 0.7
    - Empty scenario: fidelity = 1.0 (no events to miss)
  </behavior>
  <implementation>

    4. Handle positive adaptations (early completion) as NOT reducing fidelity
    5. Implement accept_reality dual-threshold logic
    6. Write comprehensive tests for all scenarios
  </implementation>
</feature>
